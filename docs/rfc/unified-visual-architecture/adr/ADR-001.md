# ADR-001 — Document Identity Model

Status：**Proposed recommendation；尚未批准**。Decision不代表正式實作或humanapproval。Current Implementation以本頁Evidence與[AUDIT](../AUDIT.md)為準。

## Context

imageIdOf以內容定義asset，createBlankCanvas用隨機PNG創canvas identity；fork setKey讓同圖已有多內容。

Evidence（CURRENT，baseline 7fb9b73442401fc32a7034888deaf49303e582a6）：`image-store.js imageIdOf / scene/blank-canvas.js createBlankCanvas / workspace.js ensureSet`；精確函數位置與sourcehash見[source index](../evidence/source-index.json)。

## Options Considered

A ImageEntry加virtual ID；B UUID Document+Scene與asset alias registry；C 全域entity graph。

## Decision

推薦B：doc UUID與asset fullhash分開；Scene只屬一Doc；legacy setKey映射一Doc。

## Rationale

Graph不需PNG；samebyte/newdoc可並存；typedprefix能拒跨domain ID。

## Consequences

增加registry與compatadapter；原img IDs保留；doc無panel也存活。 Lifecycle、ordering、async/retry與compatibility依[RFC contract](../RFC-002.md)，不從一般架構直覺補規格。

## Rejected Alternatives

A仍把pixel與lifecycle混在一起；C共享ownership/undo成本過高。

## Validation / Approval

必須通過 UVA-01/02/04/24（[case definitions](../TEST-MATRIX.md)），並完成[Open Decision OD-01](../OPEN-DECISIONS.md)簽核。Implementation Agent不得自行把推薦視為APPROVED。未列能力為Future Extension，不擴大此Decision；規格矛盾先更新ADR再進相依PR。
