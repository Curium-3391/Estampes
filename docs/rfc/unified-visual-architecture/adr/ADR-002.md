# ADR-002 — Scene 與 Marks 的關係

Status：**Proposed recommendation；尚未批准**。Decision不代表正式實作或humanapproval。Current Implementation以本頁Evidence與[AUDIT](../AUDIT.md)為準。

## Context

scene-ops管object provenance/ownership；canvas-state管user/assistant mark claims與assessment，二者已共享layers但不共享完整domain。

Evidence（CURRENT，baseline 7fb9b73442401fc32a7034888deaf49303e582a6）：`canvas-state.js applyCanvasChanges / assessment.js verificationOf / scene/scene-ops.js applySceneOps`；精確函數位置與sourcehash見[source index](../evidence/source-index.json)。

## Options Considered

A 全部轉SceneObject；B 保留兩domain、統一Layer/Interaction/Render；C generic object加rawsidecar。

## Decision

推薦B：Annotation獨立schema，typedLayer.content同時引用object/annotation，共用commands與renderplan。

## Rationale

保留evidence/verification/gesture/intent而不塞不透明props；既有Graph邏輯可沿用。

## Consequences

需要domain adapters和selection typeddispatch；禁止直接複製Graph inkengine。 Lifecycle、ordering、async/retry與compatibility依[RFC contract](../RFC-002.md)，不從一般架構直覺補規格。

## Rejected Alternatives

A遷移面大且metadata權限難凍結；C造成raw與active資料雙權威。

## Validation / Approval

必須通過 UVA-05/07/10/34（[case definitions](../TEST-MATRIX.md)），並完成[Open Decision OD-02](../OPEN-DECISIONS.md)簽核。Implementation Agent不得自行把推薦視為APPROVED。未列能力為Future Extension，不擴大此Decision；規格矛盾先更新ADR再進相依PR。
