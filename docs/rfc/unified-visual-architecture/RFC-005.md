# RFC-005 — Modules / Graph / CAS

Status：**Proposed Architecture**。CURRENT：module/1 target `none|canvas|canvas-or-new`、router.canvasContext、graph.run、CAS plotResult/after、refreshLinks見 [AUDIT](AUDIT.md)。Open Decision：OD-05（CAS user edits）/OD-06（v1適配範圍）；Future Extension：任意第三方Viewer、跨server bindings。

## Module Interface Evolution

新manifest使用 `estampes.module/2`、panel `estampes.panel/2`，package/1可攜v2 manifest但coreCompatibility必須要求支援v2的release；signed package原bytes與digest不得由adapter改寫。新增target與permissions會被目前strict v1拒絕，不能宣稱v1可透明接受。

**Example Is Illustrative Only / Not Yet Implemented**：此為target/permission欄位示例，非可安裝完整manifest（publisher/profile/runtime/version等仍依現有必要欄位）；正式schema由PR-5A補齊與凍結。target種類 `none|document|document-or-new`；scene必須指定，只有呼叫create得到defaultSceneId才可省略於同一request；不能默認最末Graph。newdoc kind必須在cap allowlist且有create grant；read permission不帶create權。

新增`execute_module`可選參數 `target:{documentId,sceneId}` 或 `createDocument:{kind,title}`；與legacy `canvas/newCanvas`互斥。擴充該工具需capability/version discovery，model讀現有tool schema；舊欄位保持可用。runtime v2 `ctx.target={documentId,sceneId,documentRevision,sceneRevision,kind,extent,objects?,annotationsSummary?}`、`ctx.grants`為此次最小權限集合；無entry/fs/DocumentStore handle。target:none給null，CAS notebooks需明確notebook範圍與cas.compute；不能由surface內其他panel推得grant。

Module permissions：`document.read.target`、`scene.write.owned`、`document.create.graph`、`document.create.image`、`document.reference.read`（明確已選doc refs）、`annotation.write.owned`（新功能需新同意）、`asset.read.selected`、`cas.compute`。新names經Store列差異與grant，不從canvas.read擴成所有doc讀取。Legacy Core/user path保舊政策；Unified path依[ANNOTATION-POLICY](ANNOTATION-POLICY.md)提供完整user editing及module author/ownership。第三方v1 adapter不給寫Marks能力；v2須annotation.write.owned新grant與publisher/lineage驗證。每個op驗document/scene scope、provenance ownership、layer lock與input/output limits。module停用/permission撤銷時，async completion重新驗lease與target expected revision，不能套用既有work(false)豁免。

Wire request `requestId`正規化為RFC002內部`commandId`；`expectedDocumentRevision`正規化為內部`expectedRevision`，二者不是兩個版本軸。new `edit_visual_document`本身已doc-scoped，可直接使用`expectedRevision`；同一工具禁止同時傳兩種名稱。legacy execute_module 的 `expectedRevision`仍代表舊sceneRevision，不可解讀成doc revision；遇兩種版本參數同傳回AMBIGUOUS_REVISION。多store CAS工具額外有expectedNotebookRevision，coordinator一次檢查完整vector。

## Legacy Compatibility Adapter

| v1 target/caller | Adapter mapping | 保留語義/拒絕條件 |
| --- | --- | --- |
| none | ctx.canvas=null；原params、原notebook store | 不自動選document；既有CAS calculate不用image |
| canvas + imageId | registry找到該default legacy set→image document；只指定scene adapter snapshot | 不選相同asset的其他copy；複本需現有可表示setId API或v2 target；否則AMBIGUOUS_TARGET |
| canvas-or-new 無canvas | **保留**createBlankCanvas→legacy image document與imageId | v1 Graph不突然改回無PNG的doc，因舊response依imageId；新v2 Graph route才獨立 |
| explicit canvas + newCanvas | 保留既有input error | 不猜哪個較新 |
| v1 manifest要求canvas但收到graph Document | default UNSUPPORTED_TARGET；核心Graph v2 route可呼叫同graph.run純邏輯，以typed context adapter提供width/height/objects | 不向第三方捏造img ID、不改權限；v1不必立刻升級仍能用image |
| v1 scene ops output | applySceneOps adapter→DocumentCommand；保留expectedRevision legacy scene projection | doc版本衝突不能轉成功；舊操作id/refs、scratch、limits保留 |

scene-ops/1仍可對legacy image adapter使用；new `estampes.document-ops/1`封裝target/expectedRevision/commandId（內部command；wire依route使用expectedDocumentRevision/requestId），其內object ops保持現有語意，新增annotation/layer/binding ops有獨立schema。既有module無須升級以維持既有功能；要graph doc/multiple targeting/annotations才升v2、重簽package並取新grant。declarative template/WASM ABI/HTTP v1 request維持原shape；v2 context需 `estampes.wasm/2` 或HTTP request schema version，不能擅改WASM ABI/1。

## Graph Document / Reuse

Graph Document是RFC002普通VisualDocument kind graph；solid background，預設Scene可空，不為身份建立axes或PNG。Graph Viewer與Image Viewer為同VisualViewer factory +不同背景/inspector defaults；annotations用同store/commands/toolbar/history。reuse `compileExpression`、`fitRange`、`pickAxes`、`sampleFunction`、axes/shape/function schemas與renderObject。將graph.run依ctx.canvas的讀取抽為bounded read context；不改expression semantics/labelMode/adaptive discontinuity policy。v2要求frame明確，僅新axes create batch可用$axes；legacy仍保留「最後一組axes」行為並記adapter。

## CAS Dependencies / Link State Machine

Current `cell.links[].canvas`沒有set/scene、object expectedRevision或user-edit guard；`after`獨立寫且失敗僅audit。Proposed Notebook schema `estampes.cas-notebook/2`：保持nb/cell/result IDs，links改bindingId+typed target；bindings在Document存target side、notebook存source side，以coordinator同commit建立，source of truth是commit binding record，不作兩個可獨立改的status。

`CasPlotBinding={id,source:{notebookId,cellId,resultId,cellRevision,environmentHash},target:Ref,lastApplied:{objectRevision,expressionHash,domainHash,resultId},policy:'pause-on-user-edit',state,reason}`。dependency graph edges definition/assumption→cell→result→binding→plot；保守依賴不能精確解析時stale整本notebook沿用，不宣稱incremental evaluator。拒環（cell讀plot或embed回路），compute queue取immutable inputs/envHash，完成時再次比較source revision與target snapshot。

狀態：`fresh → stale(upstream change) → recomputing → fresh`；backend failure→`stale/error`保留舊圖；missing target tombstone→`removed`不重建；storage unavailable→`unavailable`可重試；user修改plot語義/樣式/domain→`conflict/user-edited`暫停auto-refresh，手改axes range只改view mapping不解除cell連結。不能把CAS覆蓋user-edit作預設。

衝突選項（需explicit user command）：**保留手改並Detach**（移除live binding，保留original provenance），**以CAS更新目前圖**（明確overwrite preview+current target rev），**CAS產生新副本**（new plot/ref，原圖不動）。auto-refresh只處理stale且lastApplied==target revision/hash；manual refresh同樣需檢查，不能因按刷新就無條件覆寫。unchanged label由auto/custom政策維持；signature範圍完整含style/domain防漏。

CAS result stale不可plot；imported結果與binding全標stale-unverified，recompute前不升級fresh；resultId原值作歷史來源，fresh recompute生成新result。recompute cancel無effect；late完成source不同→discard result或存非active attempt diagnostic，不更新binding；同requestId可查狀態。多document refresh逐target分小transaction，每target完整binding+object+notebook rev vector；部分失敗逐項report、其餘可完成，無整批exactly-once承諾。permissions/module狀態每次重新驗，鎖層錯誤保持stale/conflict。UVA-19/20/21/28/31是驗收。
