## Recovery state transitions and independent selection

Each CURRENT claim retains its own claim ID, owner, hash, length, temporary name and prepared transaction. Selection is established by exact CURRENT now or an exact publication descriptor already anchored under selected CURRENT. A prepared record or a self-consistent orphan Root alone grants no selection. The descriptor must match the claim and precede the current generation; exact transaction membership binds its generation, registry and result. Existing load validation enforces unique CommitIndex generations.

Only after those independent checks are published claims ordered by authoritative generation. Distinct claims cannot repeat owner or generation; adjacent publications must have exact parentCommitHash linkage. Nonadjacent claims use the selected exact descriptors and unique generation ordering, not a guessed missing parent chain. An aborted temporary is admitted alongside newer claims only with an exact prior selected aborted classification; it gains no publication authority. Unknown/unproved owners and forged prepared sequences/ancestry fail closed. A late negative probe demonstrated that one unknown transaction could previously copy exact CURRENT bytes and be classified completed without gaining a new Ledger effect. The preserved unknown-current-owner-red log records that rejection failure. The final guard requires authoritative transaction membership plus exact selected publication even for a single matching CURRENT claim; the new normal-discovery test now rejects that forged ownership without changing CURRENT. Non-CURRENT atomic targets retain strict single ownership. No schema change or new permanent selection index was necessary because the existing selected descriptor plus authoritative generation already provides the independent ordering invariant.

Tests cover the original recovery controls, four consecutive interrupted recovery epochs after both a published and initially unselected transaction, five genuine claims, repeated cold restarts, exact original ACK, payload mismatch, unchanged Ledger cardinality and G2 cleanup after the full 24-hour grace. Existing missing/corrupt/forged historical selection tests remain unchanged. A new forged transaction-generation test preserves CURRENT and refuses startup.

## GC ownership and transitions

A new plan binds device/inode in its hashed candidates alongside content hash, length, G1/G2 class and exact source/quarantine locations. Reservations are reconstructed from the sole selected retention Root; no lockfile or in-memory map becomes another authority. Planning, stepping and cold quarantine recovery validate active/incomplete progress and ownership. Active candidates cannot share a physical object. New admission is bounded by 128 candidates per plan and 4096 active candidates across plans; temporary dispositions remain at most 64. Exceeding the bound refuses work safely. Existing retention/terminal-plan metadata scans still scale with retained history and require capacity qualification.

Transition: selected plan → quarantine rename → durable moved progress → grace/re-mark → selected unlink intent → final object/content check → unlink + directory fsync → selected deleted/terminal progress. Missing quarantine is an interrupted-unlink outcome only if the prior selected Root already authorized that exact unlink. G2 retains its 24-hour grace and conservative clock high-water behavior. Reader pins, backup dependencies and fresh live-root re-marks remain in force.

Completed/deleted candidates relinquish reservations. Recreated immutable source names are verified by content but are separate objects; active quarantine still owns only the original object. Legacy plans lacking physical identity are accepted conservatively with exclusive pathname reservations, explicitly not treating pathname equality as proof of historical object identity. Already-overlapping legacy plans fail closed; this patch does not invent deletion authorization to repair an ambiguous store.

Tests cover G1/G2 duplicate planning at planned, partial quarantine, durable unlink intent and terminal completion; repeated restarts; independently executable disjoint G1/G2 plans; valid-hash ambiguous overlapping plans; false terminal progress; existing pins/backup and legitimate content-addressed reuse. Newly eligible journal objects after a full virtual day may form a later disjoint plan: physical non-overlap is asserted instead of incorrectly requiring all later planning to be empty. The initial overly broad fixture assertion and its failed log remain preserved.

A compatibility probe also reproduced an existing baseline defect: a backup taken with an active GC plan could complete/restore, but cold opening attempted source-tree physical recovery before honoring its read-only restriction, leaving no accessible verified snapshot. Both exact baseline and pre-followup candidate fail that probe (raw backup-relocation-baseline / backup-relocation-red-corrected logs); the first probe had an unrelated unchanged-title fixture error and is retained separately. Copied device/inode reservations make the authority distinction explicit: a read-only backup must never inherit source-tree deletion rights. Restricted copies now verify complete logical closure and return read-only before physical recovery. The new regression checks documents, refusal of commit/GC and unchanged CURRENT; all seven existing backup tests also pass. Missing/corrupt logical dependencies still reject snapshot loading. No physical identities are rebound and no restore continuation is authorized.

## Filesystem trust, cache and ACK contract

[PR-1D-FILESYSTEM-TRUST-MODEL.md](PR-1D-FILESYSTEM-TRUST-MODEL.md) is the normative boundary for this candidate. Every process with the writer UID and its executable/module/preload/configuration supply chain is trusted. Enforced checks cover effective ownership, real/effective UID agreement, private nonsymlink directories, safe writable ancestry, single-link regular files, no group/other file write bits and same-device managed IO. Root-owned sticky /tmp is explicitly supported. The lease path is checked before flock creation; startup inventory and critical managed IO recheck entries; each publication audits the ancestry. Unsafe trees are refused without chmod/chown. 0644 files remain compatible behind 0700 directories.

These checks enforce ordinary different-UID Unix DAC preconditions where checked; they do not attest ACL/capability/host bypass or exclude same-UID processes. The same-UID test demonstrates that an owner can chmod a 0400 file back to writable and rewrite it inside a 0700 tree. Flock serializes cooperating clients only. A dedicated writer UID and protected executable/parent/mount with a permission-separated client interface is proposed, not activated; it would change process launch/IPC/backup compatibility. No privileged account, daemon or system-wide setup was introduced.

Reusable version and historical-registry proofs retain raw SHA-256/length plus metadata. Every fresh verification operation hashes unique reused dependencies; existing bounded prefix/metadata sharing remains provisional inside that operation. Every observed dependency is rehashed at the pre-rename and final ACK boundaries. Cache eviction discards proof, invalidation does not promote a decoded record, and restart begins empty. The 4 MiB proof budget includes digest metadata; record/registry budgets remain unchanged. Streaming digest buffers are bounded to min(file size, 4 MiB) to avoid allocating 4 MiB for each small metadata file, and reject file growth rather than chasing an unbounded stream. Existing diagnostics count load-time checks; boundary rehash work is reflected in transaction timings rather than claimed as a complete IO census.

Controlled mutation at after-prepared and current.before-rename yields no ACK, a fenced writer and unchanged CURRENT. At before-ACK, publication has already selected the new transaction: mutation detection leaves new CURRENT and its Ledger effect, fences and returns RECOVERY_REQUIRED. No older CURRENT is silently restored. A successful new ACK certifies exact selected transaction/Ledger identity after required barriers and final content verification within the stated actor/storage assumptions. Exact replay returns the original verified Ledger identity; it is not a new storage-health attestation. No ACK promises protection from corruption after the final observation or after delivery.

The original Round 3 before-ACK test remains unchanged in history and its new source-adapted replay remains visibly failing: after validating detection/no ACK/fencing, it additionally expects old CURRENT despite prior publication. That expectation conflicts with this task's explicit no-rollback requirement. A separate normal-discovery regression adds exact new generation/Ledger preservation assertions and verifies cold recovery refuses the corruption. This is not a hidden conversion of the original test to PASS.

The bounded 128-rewrite test uses real same-inode/equal-length writes. The forced alias counterexample masks only returned timestamp fields while performing real file IO/hashing, so it exercises the collision branch even on tmpfs with no observed timestamp coalescing. Neither result is substituted for native ext4 testing. Original metadata diagnostic assertions are retained as diagnostic evidence, including their historical expectation of stale proof acceptance if a real collision occurs.

## Quarantine deletion and residual adversarial risk

The final remove operation compares device/inode, byte length, metadata and SHA-256 against its immediately authorized digest after gc.before-unlink. Different-byte and identical-byte replacement inodes are retained and maintenance fences. Selected hashed plan, prior durable unlink intent, root/pin re-marks and directory fsync remain required. Known corrupt replacement content is never deliberately removed.

unlink/unlinkat operate on a pathname; holding an FD or using more stats does not make them conditional on inode/hash. A same-UID actor may still interfere after the last check or corrupt the authority chain. No actual suitable portable atomic conditional-unlink API was identified in the supported Node/Linux operations. That strong guarantee requires exclusion of other writers to quarantine, which the current same-account deployment cannot provide. R3-A1/C2 therefore remain High blockers for hostile same-UID deployment; their controlled-boundary regressions passing is narrower evidence.

## Compatibility, rollback and remaining gates

Existing stores with safe ownership/modes retain their format and exact Ledger/history identity. Recovery descriptors use existing selected-publication schema. New GC candidate physical fields are optional for reading old plans, but older strict binaries cannot read newly written physical fields: **do not downgrade in place**. Stop the writer and retain a full verified store/backup before changing code; use an isolated verified restore/reviewed repair path. Physical reservations are tied to the original tree/device; a filesystem copy/restore cannot resume active plans by merely preserving their JSON. Restricted backups remain readable after logical verification and cannot resume deletion. Legacy ambiguous overlapping stores remain fenced. Unsafe permissions/hardlinks/symlinks now intentionally refuse startup; no automatic repair or permissions migration occurs. The 4096-active-candidate bound is a new safe admission limit.

Native ext4/XFS reacceptance is unexecuted here. Checkout is overlayfs and disposable stores are tmpfs; real fsync/rename/flock/SIGKILL calls test process recovery, not physical durability. Native allowlists, M02 lease timing and the 30-second startup timeout are unchanged. Independent native full-suite/collision/boundary/state-machine/backup tests remain required. WSL host/VHDX flush, actual power loss and rollback are separate open gates.

1000-command history/checkpoint/capacity, sustained auto-maintenance/drain, 10k handwriting and large-document/pin/backup pressure remain open. 200/1000 were not attempted: mandatory correctness/resource evidence and lifecycle/deployment qualification take precedence over expanding workload here. Production ownership/isolation and old-writer fencing need independent approval/validation; no PR-1B work is started.
