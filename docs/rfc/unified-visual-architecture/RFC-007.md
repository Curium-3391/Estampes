# RFC-007 — Security / Performance / Compatibility

Status：**Proposed Architecture**。CURRENT facts：[AUDIT](AUDIT.md)，OBSERVED numbers：[BASELINE](BASELINE.md)與[evidence](evidence/benchmark-results.json)。Open Decision：OD-04（real host）、OD-06（rollout）；Future Extension：multi-tenant auth、distributed storage。

## Trust Boundaries / Threat Model

本案保留single-owner self-hosting、access-key/OAuth與現有Store/admin model；UUID不是授權，Panel存在不等於被授權。威脅來源為untrusted MCP input、manifest/package、module output、bundle、image/PDF、parent host redelivery、late async job與cross-document references。新的Document API不能把所有doc同owner視為module的全部可讀範圍。

| 邊界 | Threat / 新攻擊面 | Required enforcement / failure / tests |
| --- | --- | --- |
| Host → bridge → tools | forged/repeated/out-of-order result、過大_meta、舊binding回應 | parent來源+schema/method檢查；hydrate只讀；resultId/hash/revision去重；commandId效果去重；有限chunk與timeout；UVA-18/35/40 |
| MCP route → DocumentService | target ID混用、IDOR、跨docframe、偽user/author | typed parser、actor來route/認證、explicit target scope；doc/image alias分開；Ref resolver checked；UVA-01/28/29 |
| Manifest/package → runtime | 注入script/html/css、自訂viewer code、擴權、改簽名 | strict schema allowlist、trusted viewer kinds；v2重新簽名/compat check/Store grant；unknownkind inert；不得innerHTML/eval；UVA-28/30 |
| Runtime → ops | roguegeometry、越scope update、改別module object、lockedlayer、scratch外洩 | input/output/per-op validation、provenance ownership、lock+visibility、resource cap、atomicdraft；async finish重新驗module/grants/scope/revision；UVA-03/07/28 |
| Reference traversal | embed偷讀未選doc、cycle、大量遞迴、ref URL SSRF | execution lease含明確allowedtarget refs（不等同owner全庫）；read-onlysnapshotresolver、cycle拒絕、max embed depth8/visiteddocs12/total publicobjectlimit分配；超限placeholder+diagnostic；UVA-22/29/30 |
| Renderer → DOM/SVG/Sharp | text/path/image injection、foreignObject、external URL、SVG scripts | primitives白名單；finite值；escape text/attributes；asset handle由authorizedserver解析；PNG validated；no arbitrary SVG import rendering；UVA-10/30 |
| Bundle → migration → stores | zip traversal/bomb、hash偽造、duplicate paths/refs、unknownschemas、trustedreview偽造 | ZIP與file/schema/refs/counts分stage；hash不證作者；歷史review保留來源，不當本機新驗證；rawquarantine不執行；all-or-nonepublish；UVA-23/24/25/30 |

Object ownership沿現有user可編輯sceneobject、module只own provenance；assistant marks不可overwrite user，user move/restyle仍限自身marks；eraser可依既有policy刪assistant marks，locked一律拒。opening panel不能enable module或grant permission。cross-document embed遇拒權不能帶hiddencontent的primitives/hash進modulecontext；cache keyed authorized audience與scope，不共用privilegedcache給低權限request。

## Resource Limits / Operational Requirements

現行上限從程式核實：64 scene ops/batch、200 objects/scene canvas、60000 drawnpoints、128 points/mark、30 marks/submission、24 workspaceitems、12 panels、4 calculators、ZIP400entries/400MiB total/200MiBentry、marksfile2MiB/60marks、notebook200cells、CASclient frame4MiB、expression256chars/200tokens/200nodes/depth32、WASM2MiB/2sec/16MiB/256KiBoutput（manifest可有boundedlimits）。Graph sampler6000 eval/curve、depth7、base240。新Document command不得藉多scene繞過batch/全doc合計限制；V1全doc object/pointcaps沿200/60000，Graph多doc各自200但server總render/assetqueues有界。新增embeddepth8與12docs traverse是**Proposed security bounds**，需UVA-30驗證，非效能測量結論。

60000-point上限與現行MAX_POINTS_PER_CANVAS一致，計算**Scene Object renderer產生的points**，不把Annotation128-pointstroke突然加進舊limit。V1全Document合計200objects/60000object-renderedpoints；Annotation獨立最多5000（沿bundle/1可讀上限）、每筆128points、每submission30；完整import不經60-marklegacywidgetdisplaycap截斷，newViewer須paging/virtualization。已存在超過新限額的legacy資料保留完整readonly/可刪減與export，不自動丟到limit以下；減少容量的command可行，增加拒絕並列report。這些cap是待核准boundedlimits，不能宣稱5000筆互動效能已測。

限額超出回typed LIMIT含observed/cap/recovery suggestion，不truncate後verified:true。Document與assetcache分開，evictsnapshot可從durablegeneration恢復，不能evict唯一memory-onlydraft；memory壓力回拒新edit並提示export，禁止刪內容換取成功。對untrustedSVG/PDF/PNG保持原pixel/byte/time limits。

不新增常駐服務或公開CAS埠；既有Docker unprivileged/read-only/cap_drop/no-new-privileges，CAS network:none保留。新journal只在指定storage dir可寫，不持久化secrets至Bundle。新健康檢查顯示documentstore durable/memory、journal recovery、readonly/ENOSPC、unsupportedstoreversion；不能以HTTP200假稱所有data已saved。兩process共享volume不支援，one-writerlock second拒啟新writer；NFS rename/fsync語義未驗時不承諾durability。

## Performance Baseline / Budget Method

現在不存在multi-viewer Graph Document，不能對其製造基線數字。[benchmark.mjs](evidence/benchmark.mjs)為Phase0 research harness：合成3000×2000 image、20 curves、100×128-point strokes；2warmups/12samples；現行sampleFunction/renderCanvas/export/import。每次freshimport重設registries、用新tempdir；不讀使用者資料。報median、nearest-rank p95、Sharp/CPU/Node與endRSS；p95樣本小只作本機規劃，不宣稱productionSLO、peakmemory或speedup。

| Workload | 現況 / measurement | Proposed gate與量測責任 |
| --- | --- | --- |
| Largegraph / adaptivecurves | sample-tan與20-curve mixedrender，結果見BASELINE | 同hardware/versions/fixture、三輪獨立跑，server既有path median/p95皆<=1.25×Phase0對應值；每curve6000 eval上限不變 |
| Dense handwriting | mixed100×128points，真實max幾何不同 | Phase2補500/5000strokes（走明確limit，不能偷增cap）；supportedrange才算latency，過量測拒絕時間；sharedrender不得變更筆跡 |
| Serverrender | mixedwarm1600output，含hash/Sharpcomposite | 依measured值導出budget-table，Phase2共享renderer門檻<=1.25×；coldcache與SVG另外取基線後設gate |
| Bundle export/import | fullhash ZIP + freshstorageimport，counts/hashes一起檢查 | Phase6用相同fixture <=1.25×existingbaseline；v2更大payload另以entities/byte正規化，先量再簽budget，完整性不能因budget退讓 |
| Zoom/Pan | 現有zoom-perf fakebrowser：40wheel、imageDOM reuse、burst時間 | 保持既有assertions；補event→rAF/performance trace長task與frames，Phase3實測1/2/5viewers再凍結p95 gate，不能以zoom test名稱宣稱幀率達標 |
| Multiple viewers / panels | current只有singleCanvas，無對照runtime | Phase3 fixture 1/2/5viewers（3graph+2calc與兩視圖同doc），recordcommit→各viewport render latency、p95、DOMcount、inactiveCPU；量測後用1viewer與legacyreference差比擬budget，退出前批准，未批准不得skip |
| Multiimage workspace / hires | existing24itemcap，source20MiB/50MP、working4096、cache160MiB/12images | Phase3/6測1/6/24items、12MP/50MP；decodedasset只計一次但DOMtexturemay複製需heaptrace；超cap顯error保留資料；記RSS/heappeak後核budget |
| Resize / propagation | 尚無多viewer measurements | Phase3 measured fixture 100resize、orientation、same-doc2widgetpoll；latency門檻同hostscheduler校準，canonical geometry hash零變化是立即hardgate |
| Memory | Phase0endRSS僅snapshot | phase3 DevTools/Nodeheap peak、10openclosecycles、unsubscribe/RAF/listener counts；zero livehandles leak為hardgate，MB門檻測量後定，不使用hostMemTotal當containercap |

1.25×是**proposed regression allowance**（25%容許重構開銷），不是改善宣稱；數字由已量測同fixture值推導，需架構批准且在shared runner重測校準。本機小sample不能取代固定CI benchmarkrunner。未量測workloads只定量測方法與退出阻擋條件，不憑空寫60fps/50ms。existing correctness limit優先，不能為速度少存evidence、少取樣或不驗hash。
