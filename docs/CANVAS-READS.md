# Reading a shared canvas

`render_canvas` returns a PNG or lossless WebP of a saved canvas, including the base image, public scene objects and saved marks. It executes no module code, so saved Graph results remain readable after Graph is disabled. `process_image` continues to read only source pixels; it does not include handwriting or scene objects. The existing `image.jpg` export also remains a base-image export.

Pass `imageId`, optional `setId` (a workspace copy), normalized `region`, `maxSide` (64–4096, default 1600), `format` (`png` or `webp`), and `labels` (`none` or `all`, default `none`). The label option controls mark labels; mathematical labels, axis ticks and scene text remain part of the scene. Included object/mark IDs describe the visible layer selection, not a geometric intersection query for the crop.

The renderer follows the current widget's saved-content stacking: scene objects in object order below marks; marks in layer order, assistant marks before user marks. Layer opacity applies, and stored user marks have the widget's 0.55 fade. Locked layers are visible. Scratch is always excluded. Temporary UI decorations, selection handles, unsaved strokes, links between workspace items, and alternate processed-image tabs are not rendered. This is a saved canvas read, not a screenshot of the entire widget.

Hidden layers are local to each widget, not persisted server state. Annotation submission now sends those IDs, and the event carries `canvasReads`: one request per side or workspace item. Call `render_canvas` with that entry's `request` and an optional region. The request includes the correct `setId` for copied annotation sets, `hiddenLayers`, and `expectedRevision`. Without a supplied hidden list, all saved public layers are included.

The opaque `cv:` revision is a content fingerprint covering the image/set identity, dimensions, objects, marks, layer settings/order, and hidden list. It is separate from `image.revision: raster-v1`, which describes the base coordinate frame. If any covered state changes after submission, the old request fails with `STALE_CANVAS`; this version does not retain historical snapshots. Do not silently retry with the latest revision as if it were the original submission. Capture occurs on the server when annotations are accepted; it is not proof that a stale client was showing that revision before submission. Each render snapshots drawing inputs before asynchronous rasterization, so a concurrent edit cannot mix two states in one result.

The result reports the revision, included IDs, excluded hidden layers/scratch, effective crop after pixel rounding, output dimensions, and a row-major 3×3 `mapping.pixelToCanvasNormalized` matrix. It maps output pixel corners to normalized coordinates in that image, not to workspace placement coordinates. Cropped vectors are rasterized at delivery resolution. Enlargement of the working base image is interpolation and is reported in warnings; use `process_image` native sampling for actual source-photo detail.

Validation covers handwriting in full/cropped views, source isolation, changing Graph pixels, hidden/scratch/locked boundaries, opacity, mixed object/mark stacking, stale revisions, concurrent edits, and MCP submission/read after Graph is disabled. The complete RFC's export redesign, persistent canvas identity, focus-group labels, historical snapshots and widget synchronization are separate work.
