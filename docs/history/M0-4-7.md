# Estampes M0.4.7 — One shared visual canvas

## User feedback (2026-10-29)

The ChatGPT transcript contained **two distinct widgets** for one question:
first a Visual Surface editor (with an unavoidable intent form), followed by
a Visual Evidence image viewer (with original/marked/crop controls). The same
image appeared twice, each widget used its own accent blue, and the evidence
focus was also blue even though it did not indicate a human-authored mark.

This was an integration/UI architecture problem, not an image recognition
problem.

## Canonical flow

`inspect_visual` (model-only PNG evidence) → GPT interprets pixels and
supplies coordinates → **`present_visual` exactly once** (one inline visual
canvas, three view modes).

The single Estampes Visual Surface widget now provides:

- **標註與編輯**: the SVG scene with gold AI and blue human annotation layers,
  tools for point/rectangle/arrow, undo, clear and send-to-GPT.
- **原始圖片**: exactly the same SVG art with all overlays removed.
- **局部放大**: an unmarked SVG `viewBox` crop around the selected annotation,
  including the arrowhead rather than arrow tail. A selector picks among multiple
  AI and human marks. No second widget is spawned.
- The context form is now inside a collapsed optional disclosure. Its intent
  defaults to `point-out` when the user does not choose one, and **drawing and
  sending require no form completion**.

All three modes share the same source and normalized coordinate geometry.
They are not three separately re-rendered images. This iteration uses
**the same built-in SVG demo scenes only**; arbitrary image imports are M0.5 work.

## Design tokens and provenance

- Interaction/control blue: `#356BD6`
- **Human-authored** marks: `#579DF6`
- **AI-authored** marks: `#E4AE57`
- Technical inspection focus, when using the standalone legacy PNG tool:
  neutral slate `#64748B`, not a human/AI authorship claim

The standalone `present_visual_evidence` tool remains available for old
conversations and explicit standalone PNG requests, **but must not be used
after `present_visual` in a normal visual task**. Its new UI resource URI
is `ui://estampes/visual-evidence-v047.html`. Historical `v045` continues
to resolve. The canonical canvas now uses
`ui://estampes/visual-surface-v047.html` with `v046` compatibility.

## Acceptance checklist in ChatGPT (not automatically proven by CI)

1. Open `/version` and confirm `m0.4.7`,
   `visualDisplayTool=present_visual`, and
   `visualCanvasModes=[annotated,original,zoom]`.
2. Refresh Estampes tools and start a new chat to avoid cached widgets.
3. Ask the model to use `inspect_visual` to inspect the real demo landscape
   and use `present_visual` **once** to mark a chosen region, supplying
   normalized coordinates based on its own image inspection.
4. **Only one Estampes visual widget** should appear.
5. On the same widget, switch between 標註與編輯, 原始圖片,
   and 局部放大. Original and zoom have no overlay marks; editor
   marks retain author colors and identities.
6. Add a point on the house and another near the tree. In zoom mode change
   the focus selector: the crop must move to the chosen focus. Return to
   annotate mode and continue drawing.
7. Without opening the context form, press 把標註傳給 GPT. A new message
   must include intent `point-out`, normalized geometry, and correct author.
8. Explicitly test the standalone `present_visual_evidence` only as a
   **legacy compatibility case**, not in the same normal exchange.

## Limitations

- In M0.4.7 the combined canvas's user-facing original/zoom uses an SVG
  `viewBox` and existing SVG source, **not new PNG pixel blobs**. This is
  visually accurate for our local vector demo but does not yet generalize
  to arbitrary raster images.
- `inspect_visual` still emits genuine PNG image blocks for model vision
  and has a separate host-visibility uncertainty.
- The host is free to choose tools: metadata strongly guides the one-widget
  flow, but code cannot guarantee that an LLM will never explicitly invoke
  the legacy renderer as well.
- Annotation state across independent ChatGPT tool cards is not yet a
  durable shared store.
