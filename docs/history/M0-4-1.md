# M0.4.1 — Grounding and provenance correction

## Bug report (ChatGPT host, 2026-10-29)

The model was asked to mark a mountain on the built-in landscape. It placed the mark on the foreground tree, then stated the mountain was correctly marked. On a subsequent call, previously human-authored marks `YOU 1` and `YOU 2` were redrawn in the assistant's gold annotation layer. Both are incorrect behaviors.

## Root causes

1. **Coordinate validation is not semantic grounding.** M0.4 checked that `x/y` fell within `[0,1]`; it never verified that the coordinate corresponded to the named object. The model received scene descriptions, not a trustworthy grounding oracle.
2. **Replaying annotations lost authorship.** `present_visual` previously treated all model-supplied marks as assistant annotations. The widget reset user marks whenever it loaded an input snapshot.

## Focused M0.4.1 fix

- A deterministic geometry catalog for built-in SVG samples now supplies landmark IDs:
  - `landscape`: `sun`, `house`, `house-roof`, `tree`, `mountain-left`, `mountain-right`
  - `shapes`: `circle`, `square`, `triangle`
  - `formula`: `equation`, `equals-sign`
- The model can request `{ "type": "point", "targetId": "mountain-right" }`. The **server**, not the model's guessed coordinates, resolves the visible mountain to `x=0.5625, y≈0.3611`.
- Unanchored free-coordinate AI marks remain possible, but now carry `grounding: "unverified"`; the widget prefixes their label with a question mark.
- Model-provided `annotations` represent **new assistant** marks. `priorUserAnnotations` is a separate parameter for earlier user marks, replayed with `author:"user"` and blue styling.
- `user-*` IDs and `YOU ...` labels passed as new AI marks are rejected as a basic guard against accidental reauthoring.
- Occluded mountain regions cannot be represented by a single honest tight rectangle. Target-based mountain **rectangles are rejected**; use a point until polygon/mask support exists.
- This is not persisted or authenticated authorship. `priorUserAnnotations` are replayed data supplied from conversation context, not an access-controlled database.

## Example: accurately mark the right mountain

```json
{
  "scene": "landscape",
  "annotations": [
    {"id":"mountain","type":"point","targetId":"mountain-right","label":"山"}
  ],
  "priorUserAnnotations": [
    {"id":"user-1","type":"point","x":0.2094,"y":0.5815,"label":"YOU 1"},
    {"id":"user-2","type":"rect","x":0.6301,"y":0.2344,"x2":0.9651,"y2":0.9379,"label":"YOU 2"}
  ]
}
```

The returned normalized annotations include explicit author and grounding status. The previous user marks should remain blue and the new mountain point should be gold **on the mountain**, not on the tree.

## Important limitations

This solves grounding **only for known demo SVG scenes with explicit landmark data**. It does not make arbitrary-image grounding accurate. For photos and images gathered by GPT, the next step requires an authorized actual image resource, image identity/revision, a vision grounding pass (object boxes or segmentation), and independent location verification. Until then, model-generated `x/y` should be treated as unverified.

M0.4.1 does not provide multi-turn state persistence, verified provenance, mask/polygon annotation, or direct control of native ChatGPT images.
