# Estampes M0.4.2 — Context-aware Annotation Sending

M0.4.1 fixed semantic anchors and reauthoring in known SVG scenes. M0.4.2 addresses another limitation: **a point, box or arrow without the speaker's communicative intent is ambiguous**.

## Changes

- New canonical protocol: [Annotation/Context v0.2 draft](PROTOCOL-V0.2.md).
- `present_visual` keeps the same built-in scenes and `targetId` behavior.
- The visual widget now requires an explicit purpose before submitting marks.
- Optional text fields: a short **user note** and **manually typed prior utterance**.
- The app-only `validate_visual_annotations` accepts `intent`, `note`, and `replyQuote` and returns:
  - `event`: canonical `schemaVersion: "0.2-draft"` envelope
  - `chatMessage`: server-generated conversational message including intent, optional note/quote and JSON payload.
- `ui/message` sends the canonical text; if validation fails, the widget marks the data **unverified** and attempts a limited fallback.
- The input image identity and SVG logical dimensions are explicit; unknown photographic resolution and DPI are `null`.

## ChatGPT manual acceptance test

1. Open [the deployed version endpoint](https://estampes-mcp.onrender.com/version) and confirm `m0.4.2` with `ui://estampes/visual-surface-v042.html` and `annotationProtocol: "0.2-draft"`.
2. Refresh the Estampes custom MCP tool list if necessary. Start a new ChatGPT conversation.
3. Use `present_visual` with `scene: "landscape"` and an AI point using `targetId: "mountain-right"`.
4. Draw a user **arrow** from the house toward the tree.
5. Select **更正你之前指錯的位置**, and enter a note such as **我指的是樹，不是山。**
6. Optionally type a verbatim previous question in the quote field; do not invent one if you have none.
7. Press **把標註傳給 GPT**.
8. Confirm an actual **new user message** appears with `"schemaVersion":"0.2-draft"`, `intent: "correct-assistant"`, `requestedAssistantAction: "reconsider-prior-identification"`, `arrowMeaning: "arrowhead-is-target"`, scene `demo:landscape`, and intrinsic size in `svg-user-unit`.
9. Confirm the GPT response addresses the **correction**, not merely listing coordinates. If the prior question was not visible to the host and no user quote was provided, GPT must not invent it.
10. Repeat with an empty note, with two annotations, and after resizing the window.

## Automated checks

`npm test` now includes:

- `tests/interaction-protocol.test.js`: source geometry, arrow semantics, intents, user-provided quoted context, length limits and missing-context honesty.
- `tests/visual-widget.test.js`: presence of intent selector, note and quote fields, explicit validation and chat-message path.
- `tests/mcp-http.test.js`: the private validator returns protocol v0.2 `event` and `chatMessage`, plus existing old-tool and resource checks.

## Deliberate limits

- The plugin does **not** automatically see chat history, select a prior message, or access native ChatGPT images. `replyTo.messageId` is null.
- This does **not** implement CV edge detection, object detection or snapping. Those should be optional and reversible, with clear evidence that any suggested geometry differs from a human mark.
- No persistence/authentication is included. The hosted endpoint is public, so avoid confidential notes or conversation excerpts.
- Passing the unit and dimensions to the model does **not** grant actual image perception or fix general semantic grounding.

**Do not mark this version fully working until tested in the live ChatGPT host.**
