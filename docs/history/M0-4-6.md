# Estampes M0.4.6 — Remove the scene-anchor answer key

## Failure observed in ChatGPT on 2026-10-29

The user's screenshot showed an assistant-generated blue focus at normalized
`(0.25, 0.736111...)`, exactly matching the former hard-coded
`sceneLandmarks.landscape.house` point `(160/640, 265/360)`.

The model explicitly explained that the location came from Estampes's `house`
scene anchor. Therefore the location *cannot* count as independent evidence
that the model recognized or localized a house from image pixels, even if the
model also saw the image when answering.

## Fix

- Public `present_visual` accepts **only x/y coordinates** (plus x2/y2 for
  rectangles and arrows). The input schema is strict: `targetId` is rejected.
- Public tool descriptions no longer list named objects or their coordinates.
- The old semantic landmark catalog remains in `src/scene-catalog.js` for
  internal unit tests and historical reference. It is **not a model-callable
  visual grounding service**.
- Image interpretation remains GPT's responsibility. The proper sequence for
  a model that must *locate* an object is `inspect_visual` (real source PNG
  evidence) followed by `present_visual` (coordinates proposed after looking).
- `present_visual_evidence` remains the separate verified image viewer,
  rendering the full original, blue-marked view, and unmarked crop.
- Versioned `ui://estampes/visual-surface-v046.html` prevents stale
  UI template reuse in new conversations.

## What this fix **does not** prove

Removing the answer key removes one source of target leakage. It **does not**
guarantee the ChatGPT host exposes MCP image blocks to model vision, and does
not establish that the model's chosen coordinate is visually correct.
The fixed demo landscape is familiar from previous messages and may also
be memorized from prior turns. Treat its successful identification as a smoke
test, not as a blind visual-grounding score.

## Acceptance smoke test

1. Verify `/version` gives `m0.4.6` and
   `visualGroundingMode: coordinates-only-no-object-anchors`.
2. Refresh Estampes tool definitions; open a **new conversation**.
3. Ask ChatGPT: "請先呼叫 Estampes inspect_visual，真正觀察 landscape
   原始圖片，自己找出房子，再用 present_visual 的座標在房子上標點；
   不要使用預設物件 ID、歷史錨點或手動查 repo。"
4. Confirm `inspect_visual` ran **before** any coordinate-based marking.
5. Confirm `present_visual` was called with explicit `x/y`, not `targetId`.
6. Check that the point is actually inside the house by looking at the returned
   picture. A correct point on this same familiar demo is a smoke test only.

## Proper blinded evaluation (next milestone)

- Use new images not already shown in chat, with no filenames or metadata
  naming the target.
- Randomize object positions and visual attributes per trial (e.g., controlled
  SVG generated from a seed); don't send their semantic layout to the model.
- Provide only real image pixels, image dimensions, a neutral image ID, and
  the user question.
- Record tool call order, model-proposed coordinates, and independently
  evaluated target region masks.
- Add counterfactual trials where the same nominal filename/scene ID
  corresponds to differently arranged pixels; answers must track the pixels.
- Count uncertainty and mistakes, not just successes.

**Trust boundary:** Estampes owns pixel processing and coordinate transforms;
GPT supplies object interpretation; the user's actual annotation and intent
must never be silently rewritten.
